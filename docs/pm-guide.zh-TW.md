# Straw Boss Desk 使用說明（給 PM）

這份說明寫給用 Straw Boss Desk 的 PM。它是一個桌面應用程式：第一次開啟時，它會把這台電腦準備好（安裝工具、登入你的程式碼平台和 Claude），之後打開就是 Straw Boss 的工作畫面。

目前是試用階段，應用程式還沒有簽署。所以第一次開啟時，Windows 和 macOS 都會多問你幾句，下面各有一節說明該怎麼回答。

> **截圖欄位**：標有「【截圖待補】」的地方，會在 Windows 虛擬機（任務 16）和 macOS 乾淨環境（任務 17）實際走過一次之後，換成繁體中文的真實畫面。圖檔放在 `docs/images/`，檔名已經寫在欄位裡。在那之前，文字說明就是依據。

## 開始前先知道的事

- **安裝位置不需要系統管理員密碼。** 應用程式本身裝在你自己的使用者資料夾，它安裝的所有工具都放在它自己的資料夾（下面叫「資料夾」）裡，不會動你原本裝的 Node、Git 或其他工具。
  - Windows：應用程式在 `%LOCALAPPDATA%\Programs\straw-boss-desk`，資料在 `%LOCALAPPDATA%\straw-boss-desk`。
  - macOS：應用程式在你拖進去的位置（通常是「應用程式」資料夾），資料在 `~/Library/Application Support/straw-boss-desk`。
- **第一次設定要下載數百 MB**，需要數分鐘，要能連上網路。
- **你的專案不在這個資料夾裡。** 專案放在你在設定時選的「工作資料夾」，Straw Boss 自己的資料不會混進去。
- **如果團隊的程式碼主機只開放公司網路**（例如要連公司的 VPN 或 Tailscale 才連得到），請先連上那個網路再開始。Straw Boss 不會替你安裝 VPN。連不到時，畫面會指出是哪一台主機。
- **在 Mac 上用虛擬機跑 Windows，而且 Mac 開著 Cloudflare WARP 時，虛擬機會連不到 GitHub 和部分憑證主機**；把 WARP 關掉再試。直接在你的筆電上執行不受影響。

## 在 Windows 安裝

1. 下載安裝檔 `straw-boss-desk-Setup-<版本>.exe`。
2. 用 Edge 下載時，Edge 可能說這個檔案「不常下載」。點檔案旁的選單，選「保留」。

   【截圖待補・任務 16】`docs/images/windows-edge-keep.zh-TW.png`：Edge 的「不常下載」警告與「保留」。

3. 開啟安裝檔。Windows 可能跳出藍色的「Windows 已保護您的電腦」。點「其他資訊」，再點「仍要執行」。

   【截圖待補・任務 16】`docs/images/windows-smartscreen.zh-TW.png`：SmartScreen 的兩個畫面。

4. 安裝會自己跑完，不會問你要裝到哪裡，也不會要密碼。裝完後應用程式會自己開啟。
5. 之後的更新，應用程式會自己下載，你按「重新啟動並更新」就好。

### 如果應用程式完全打不開：Smart App Control

全新安裝的 Windows 11 可能開著「Smart App Control」。它會直接封鎖沒有簽署的程式，**而且沒有「仍要執行」可以按**，所以 Straw Boss Desk 在這種電腦上連視窗都不會出現。

目前試用階段的做法：

- **開著 Smart App Control 的電腦，暫時不支援。**
- **請不要為了裝它而把 Smart App Control 關掉。** 在部分 Windows 版本上，關掉之後沒辦法再打開，除非重灌 Windows。
- 請直接聯絡我們，我們會替你換一台電腦或等簽署版本。簽署之後，開著 Smart App Control 的電腦就能用。

看你的電腦有沒有開：「設定」→「隱私權與安全性」→「Windows 安全性」→「應用程式與瀏覽器控制」→「智慧型應用程式控制設定」。

【截圖待補・任務 16】`docs/images/windows-smart-app-control.zh-TW.png`：這個設定頁。

「評估」模式（尚未決定開或關）的電腦現在可以執行，但 Windows 之後可能自己把它打開，到時就會封鎖。歡迎畫面會提醒你。

## 在 macOS 安裝

1. 下載 `.dmg`，打開，把 Straw Boss Desk 拖進「應用程式」。
2. 第一次開啟時，macOS 會說無法驗證這個 App。**macOS 15 以後，在 App 上按右鍵選「打開」已經沒有用了。** 做法是：
   1. 先照一般方式開一次（會被擋下，關掉那個訊息）。
   2. 打開「系統設定」→「隱私權與安全性」，往下捲到最底，找到關於 Straw Boss Desk 的訊息，點「仍要打開」。
   3. macOS 可能要你輸入系統管理員密碼。**公司配發的 Mac 常常沒有這個權限**；這種情況請找管理電腦的人，或聯絡我們。

   【截圖待補・任務 17】`docs/images/macos-open-anyway.zh-TW.png`：「隱私權與安全性」裡的「仍要打開」。

3. 之後的更新，應用程式會告訴你有新版，並下載新的 `.dmg`；你再拖一次進去。
4. 更新之後，macOS 可能再問一次，是否允許 Straw Boss Desk 使用鑰匙圈裡它自己的項目。請按「允許」。

## 登入程式碼平台時，說「這台電腦已經有登入」

設定中，Straw Boss 會幫你登入 GitHub 或 GitLab。如果它停下來說：

> 這台電腦上已經有一個來自其他程式的 github.com 登入，很可能是你自己的 GitHub 命令列工具。Straw Boss 若要登入就得取代它，所以先在這裡停下，並保留你原有的登入。

（GitLab 時是「gitlab.com」和「GitLab」；主機和工具名稱依你的情況而定。）

這是 Straw Boss 在保護你。`gh`、`glab` 這類命令列工具把登入放在系統的憑證儲存區（Windows 的「認證管理員」、macOS 的鑰匙圈），名字只取決於主機，所以 Straw Boss 的登入會**蓋掉你自己的**，登出時還會把它刪掉。為了不傷到你的登入，它選擇停下來。

怎麼辦：

- 如果你平常就用 `gh` 或 `glab` 在這台電腦登入，這一步請選「稍後」。這一步就先不做，你的登入原封不動；之後想登入，可以在「設定」裡再做。
- 「詳細資料」會列出它找到的項目名稱，讓你確認是不是你自己的。
- 如果那個項目確實不是你的（例如是之前 Straw Boss 留下的，被別的程式改過），做法在[手動移除留下的登入](#手動移除留下的登入)。刪掉之後，「重新登入」就能繼續。

另一種情況：Straw Boss 自己做的登入，事後被你的 `gh auth login`、或代理程式執行的 `gh auth refresh` 改過。這時 Straw Boss 把它當成你的，「登出」和「重新登入」會停下來並說明，它留下的項目也要照同一節手動處理。

## 已知的限制

### 電腦裝了 Windows Subsystem for Linux（WSL）

這台電腦有 WSL 時，代理程式啟動的 `bash` 會是 WSL 的，所以**代理程式不能把工作派給子代理**。其他功能都正常。歡迎畫面和橫幅會告訴你這件事，「詳細資料」會顯示 `bash` 實際指向哪裡。

這需要上游的 pi-herdr-agents 修正。修正（PR #112）已在 2026-11-04 合併到上游，等它發行新版、我們再更新鎖定的版本之後才會生效；那是別人的專案，無法保證日期。試用階段，有 WSL 的電腦仍然支援，只是沒有子代理。

### Windows 上關閉視窗，會讓所有代理程式停止

在 Windows，關掉 Straw Boss 的視窗就是結束應用程式，**正在工作的代理程式會立刻中斷**，而且目前沒辦法先警告你。下次開啟時，工作區會恢復，但被中斷的那一輪工作要重做。

所以代理程式還在跑的時候，請不要關視窗；最小化就好。macOS 關視窗不會結束，要用「結束」才會停。

### Claude 的登入在 Windows 是純文字檔

Claude Code 在 Windows 把登入存成一個純文字檔 `.credentials.json`，放在 Straw Boss 自己的 `claude` 資料夾裡。任何以你的身分執行的程式都讀得到。這是 Claude Code 的設計，不是我們能改的。macOS 則放在鑰匙圈裡自己的項目，和你自己的 Claude Code 登入分開。

「移除所有資料」會把這個檔案連同資料夾一起刪掉。

### 以系統管理員身分執行

支援。不過一般用法就是直接開啟，不需要「以系統管理員身分執行」。如果出現說 Straw Boss 的資料夾有 Administrators 群組規則而無法啟動，請找管理這台電腦的人移除那條規則。

## 診斷與修復

「設定」→「診斷」有四張卡片：

- **狀態**：按「檢查狀態」，會讀 Straw Boss 服務自己回報的狀況（運作中與否、版本、是不是由這個應用程式啟動）。要幾秒鐘。
- **記錄檔**：「開啟記錄檔資料夾」。記錄檔已經遮蔽了密碼和登入資料。
- **收集診斷資料**：做出一個 zip 放到你的「下載」資料夾，並在檔案總管（Finder）裡指給你看。它只包含記錄檔和設定的狀態，**沒有**你的專案、登入、金鑰，也沒有任何程式的設定檔。把它交給協助你的人。
- **修復**：檢查設定的每一個部分，把缺少或壞掉的重新安裝（例如不小心刪掉的外掛、被移走的 PATH 項目）。修復時 Straw Boss 會先停止，做完再啟動，需要幾分鐘。

遇到「Straw Boss 無法啟動」，第一步通常是「修復」，第二步是「收集診斷資料」。

## 移除

**先在應用程式裡按「移除所有資料」，再解除安裝。** 順序不能反過來：

- 解除安裝只會移除程式本身，**資料夾和你的程式碼平台登入都會留下**，這樣你之後重新安裝時還能接著用。
- 登入（gh、glab 的登入資料）存在 Windows 的「認證管理員」或 macOS 鑰匙圈。只有應用程式能分辨哪些是它自己做的，所以要由它登出。

步驟：

1. 開啟 Straw Boss Desk →「設定」→「電腦」→「移除所有資料…」。
2. 確認畫面會告訴你：
   - 要刪的資料夾和大小；
   - Windows：要從使用者 PATH 拿掉的那一項；
   - **你的工作資料夾和裡面的專案會保留**；
   - 哪些登入項目**會留下來**，每一個都有原因：「被改過」、「別的程式建立的」，或「同一個網站還有別的登入」。
3. 按「移除所有資料」。它會停止服務、登出 Claude 和程式碼平台、刪除 Linear 金鑰、刪除檔案。
4. 完成後的畫面會列出留下的項目和沒完成的步驟。它維持開啟，是為了讓你看完；你關閉它時才會刪最後一個資料夾（瀏覽器元件用著的那個）。若關閉時沒刪成功，下次開啟會先把它做完。
5. 然後解除安裝：
   - Windows：「設定」→「應用程式」→「已安裝的應用程式」→ Straw Boss Desk →「解除安裝」。
   - macOS：把 Straw Boss Desk 從「應用程式」拖到垃圾桶。

如果「移除所有資料」沒有辦法開始，它會說明為什麼，並且**什麼都沒刪**：

- 「憑證儲存區沒有回應」：鑰匙圈被鎖住或「認證管理員」出問題，它分不出哪些是自己的，所以不動。解鎖或重新啟動電腦後再試。
- 「Straw Boss 啟動的一些程式還在執行」：畫面會列出程式的完整路徑與處理程序編號。關閉它們或重新啟動電腦，再試一次。
- 「Straw Boss 正在做另一件事（更新或關閉）」：等它做完再試。

如果你已經先解除安裝了：資料夾和登入還在。重新安裝同一版 Straw Boss Desk，照上面的步驟做「移除所有資料」，再解除安裝一次。

## 手動移除留下的登入

「移除所有資料」只登出 Straw Boss 自己做的登入。有些項目它不會動，會在確認畫面和結果裡逐一點名，每一個都有原因：

- **同一個網站還有別的登入**：這一筆是 Straw Boss 建立的，內容沒有被動過；但同一個網站在這台電腦上還有別的登入（多半是你自己用 `gh auth login` 或 `glab auth login` 登入的）。登出會連你的那一筆一起刪掉，所以 Straw Boss 兩筆都沒動。**這一筆可以刪**：它的帳號欄和畫面上點名的那一筆一致，刪掉不影響你自己的登入。**不要刪你自己的那一筆**（畫面上標「別的程式建立的」、帳號不同的那一筆）。
- **被改過**：Straw Boss 做的，但後來被你的 `gh` / `glab` 或某個代理程式重寫過，現在裡面可能是你的登入資料。**只有在你確定它不是你自己的登入時才刪。** 如果你在這台電腦上用自己的 `gh` 或 `glab` 登入過同一個網站，就不要刪，刪了你就要重新登入。
- **別的程式建立的**：Straw Boss 沒做過它，不歸 Straw Boss 移除。同樣，只有在你確定它不是你自己的登入時才刪；如果你從來沒有在這台電腦上用自己的工具登入過這個網站，刪掉它是安全的，之後 Straw Boss 的「重新登入」就能運作。
- **移除失敗**（只在結果畫面出現）：Straw Boss 建立、仍屬於它，但這次沒有刪成功。**這一筆可以刪**，做法同下。

項目名稱長這樣：

| 平台 | 項目名稱 |
| --- | --- |
| GitHub | `gh:github.com`（或你的 GitHub 主機）、`gh:_refreshable:<主機>` |
| GitLab | `glab:<主機>:token`、`glab:<主機>` |

名稱後面的「帳號」是登入的使用者；同一個主機可能有好幾筆。畫面上點名的那幾筆，就是要找的。

### 在 macOS：鑰匙圈存取

1. 開啟「鑰匙圈存取」。macOS 15 以後它不在「應用程式」→「工具程式」裡了，請用 Spotlight（按 ⌘ 加空白鍵）搜尋「鑰匙圈存取」。
2. 左邊選「登入」，上方分類選「密碼」。
3. 在右上角搜尋框輸入畫面上點名的名稱，例如 `glab:gitlab.example.com:token`。
4. 點選那一筆，確認「種類」是「應用程式密碼」、名稱和畫面上的一致。
5. 按右鍵，選「刪除」，確認。
6. 回到 Straw Boss，按該主機的「重新登入」。

【截圖待補・任務 17】`docs/images/macos-keychain-delete.zh-TW.png`：鑰匙圈存取中搜尋並刪除一筆的畫面。

### 在 Windows：認證管理員

1. 開始功能表搜尋「認證管理員」，開啟。
2. 選「Windows 認證」。
3. 在「一般認證」底下，找名稱以畫面上點名的字開頭的項目，例如 `glab:gitlab.example.com:token:`（Windows 會在後面接上帳號）。
4. 點開那一筆，確認名稱，按「移除」，確認。
5. 回到 Straw Boss，按該主機的「重新登入」。

【截圖待補・任務 16】`docs/images/windows-credential-manager-delete.zh-TW.png`：認證管理員中展開並移除一筆的畫面。

不要刪名稱看起來像 `git:https://github.com` 的項目，那是 Git for Windows 或別的 Git 工具存的，跟 Straw Boss 無關。

### 結果畫面說「沒完成」的步驟

只有「刪除檔案」這一步，Straw Boss 會在你關閉它時再試一次。其他步驟不會自動再試，請照下面自己處理：

- **登出程式碼平台**：照上面的做法，刪掉畫面上點名的那一筆。
- **登出 Claude**：
  - macOS：在鑰匙圈存取搜尋 `Claude Code-credentials-`，名稱後面接 8 個字元的就是 Straw Boss 的那一筆（沒有這 8 個字元的是你自己的 Claude Code，不要刪）。
  - Windows：Claude 的登入通常是 Straw Boss 資料夾裡的 `claude\.credentials.json`，會隨資料夾刪掉。若你的 Claude 把登入放在「認證管理員」，請在「一般認證」裡找名稱含 `Claude Code` 的項目；如果你自己也用 Claude Code，無法分辨時請聯絡我們，不要猜著刪。
- **移除 Linear 金鑰**：它存在 Straw Boss 資料夾的 `secrets` 裡，刪掉資料夾就沒有了。
- **移除 PATH 項目**（Windows）：開始功能表搜尋「環境變數」，選「編輯您帳戶的環境變數」，在上方「使用者變數」選 `Path`，按「編輯」，刪掉結尾是 `\tools\shims` 的那一行。
- **移除鑰匙圈裡的金鑰**（macOS）：在鑰匙圈存取搜尋 `Straw Boss Desk Safe Storage`，刪掉那一筆。
- **刪除檔案**：關閉 Straw Boss 時會再試一次。仍然刪不掉時，請關閉所有用到那個資料夾的程式，再自己刪除結果畫面上寫的資料夾。
